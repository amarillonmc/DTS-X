## 性能实测与环境问题

Windows 本机已激活账号的完整 `command_game` 视图请求 5 次均返回 200 和完整 `gamecmd`，耗时 2,075–2,195 毫秒，中位 **2,121 毫秒**；新闻请求为 2,072–2,381 毫秒，中位 **2,212 毫秒**。随后匿名请求返回原登录提示，没有继承登录态。原 daemon 常驻模块的性能特征并未等同保留，当前每次 PHP 请求仍需加载模块；这些数值不能外推 Linux，也不是多人容量承诺。证据为 `var/benchmark-live-game.json`。

验收早期模板缺失的根因已经通过火绒隔离记录确认：1,023 个 DTS-X 路径被隔离，其中 539 个位于实际服务的 `var/game` 模板目录，报告名称为 `HEUR:Backdoor/PHP.WebShell.g`。独立纯 Node 写入原始 178 字节天气模板后，文件立即存在、约 500 毫秒后消失，和隔离记录相符；这不是已证实的 PHP/WASM 文件系统实现缺陷。证据为 `var/antivirus-dts-evidence.json`。用户已处理真实模板目录的信任，随后全量编译和游戏验证通过；助手没有修改或关闭防护设置，也没有添加写入重试掩盖文件消失。

测试期间还出现两次独立的 Windows Node 原子替换 `EPERM`：分别为临时夹具的 `server.config.adv.php` 与 `modulemng.config.php`，当时完整套件分别 23/24、26/27 通过。审查确认夹具根目录唯一、写入串行 await、失败测试没有建立 PHP 或这些目标的锁；独立纯 Node 连续原子替换 200 次无失败。具体占用句柄或外部来源尚未确定，不能直接归因为上述火绒隔离。未增加重试或扩大信任范围；之后完整复测和最终测试均 27/27 通过。完整错误、路径、堆栈与探针结果保存在 `var/atomic-rename-audit.json`、`var/atomic-rename-probe-result.json`，这些偶发失败仍属于 Windows 部署需要留意的边界。

## 发布前及公测时继续验证

保留全部代码与通过上述测试，不等于已逐个玩过 770 个模块的所有组合。以下场景应在隔离服按目标运营模式记录玩家、操作、预期与实际结果：

- 两人及多人同时攻击、同一物品争抢、战斗死亡、反击、复活与复杂技能连锁。
- 各种房间的人数、准备、踢人、旁观、切换、取消和跨房状态隔离。
- 禁区时钟、自动开局、NPC 行为、长局结算、结局选择及完整录像回放。
- 跨服账号、排行和远程录像服务的真实配置与互通；这些需要相应外部服务。
- 目标 VPS 的 Docker 构建、冷启动、反向代理 HTTPS、停服备份恢复和预期并发压测。

本机没有 Docker 引擎，因此不能把本地 Node + MariaDB 的成功等同于已实际跑过 Compose。部署文件提供了固定依赖、健康检查、独立数据库与持久卷，仍应在目标 VPS 做首次验收。
